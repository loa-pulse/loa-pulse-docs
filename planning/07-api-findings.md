## 인증과 호출 제한

| 항목 | 확인 결과 |
|---|---|
| 발급 | developer-lostark.game.onstove.com에서 클라이언트를 만들면 API Key(JWT)가 발급된다. 클라이언트는 5영업일 안에 검토된다 |
| 인증 헤더 | `authorization: bearer {API Key}` |
| 호출 제한 | 클라이언트당 **분당 100회** |
| 제한 헤더 | `X-RateLimit-Limit`(100), `X-RateLimit-Remaining`(남은 횟수), `X-RateLimit-Reset`(다시 채워지는 시각, Unix 초) |
| 키 보관 | 저장소 밖 파일(`~/.config/loapulse/env`)의 `LOSTARK_API_KEY` 환경변수. 저장소에는 올리지 않는다 |

`X-RateLimit-Reset`이 응답 시점의 약 1분 뒤였다. 1분 단위로 횟수가 다시 채워지는 방식으로 보인다. 정확한 동작(고정 구간인지 이동 구간인지)은 `TODO`.

## 거래소 엔드포인트

| 엔드포인트 | 용도 | 비고 |
|---|---|---|
| `GET /markets/options` | 카테고리, 등급, 티어, 직업 목록 | 거의 바뀌지 않으므로 시작할 때 한 번만 호출하면 된다 |
| `POST /markets/items` | 카테고리 검색. 한 페이지에 여러 아이템의 현재 시세 | **수집의 주력 엔드포인트** |
| `GET /markets/items/{id}` | 아이템 하나의 최근 14일 일별 평균가와 거래량 | 차트용 |

### 검색 (`POST /markets/items`)

요청 예시:

```json
{ "Sort": "CURRENT_MIN_PRICE", "CategoryCode": 50010, "PageNo": 1, "SortCondition": "DESC" }
```

- `ItemGrade`(예: `"유물"`), `ItemName` 등으로 범위를 좁힐 수 있다.
- **한 페이지는 10개 고정**이다 (`PageSize: 10`). 페이지 크기를 바꾸는 파라미터는 확인하지 못했다.
- 응답: `PageNo`, `PageSize`, `TotalCount`, `Items[]`

`Items[]`의 필드:

| 필드 | 의미 | 예시 (운명의 파괴석 결정) |
|---|---|---|
| `Id` | 아이템 ID | 66102007 |
| `Name`, `Grade`, `Icon` | 이름, 등급, 아이콘 URL | |
| `BundleCount` | 묶음 단위. 가격은 이 묶음 기준이다 | 100 |
| `CurrentMinPrice` | 현재 최저가 (골드) | 829 |
| `YDayAvgPrice` | 전일 평균가 | 894.5 |
| `RecentPrice` | 최근 거래가 | 829 |
| `TradeRemainCount` | 남은 거래 가능 횟수. 거래 횟수 제한이 없는 아이템은 `null` | null |

### 상세 (`GET /markets/items/{id}`)

- 배열로 온다. 같은 아이템이라도 **`TradeRemainCount`가 다르면 별도 항목**이다. 예를 들어 유물 각인서는 "귀속 후 1회 거래 가능"(1)과 "거래 불가"(0) 두 항목이 왔다.
- 항목마다 `Stats[]`에 최근 14일의 `{ Date, AvgPrice, TradeCount }`가 날짜 내림차순으로 온다. 첫 항목은 오늘(집계 중)이다.
- `ToolTip`은 게임 내 툴팁을 담은 JSON 문자열(HTML 태그 포함)이다. 저장하지 않는다.

## 카테고리별 아이템 수

카테고리 코드별 `TotalCount`와, 전부 수집할 때 필요한 호출 수(10개당 1회).

| 코드 | 카테고리 | 아이템 수 | 호출 수 |
|---|---|---|---|
| 40000 | 각인서 | 86 | 9 |
| 50000 | 강화 재료 | 98 | 10 |
| 60000 | 전투 용품 | 50 | 5 |
| 70000 | 요리 | 73 | 8 |
| 90000 | 생활 | 34 | 4 |
| 100000 | 모험의 서 | 140 | 14 |
| 140000 | 펫 | 101 | 11 |
| 160000 | 탈것 | 64 | 7 |
| 110000, 170000, 220000 | 항해, 기타, 보석 상자 | 7 | 3 |
| 20000 | 아바타 | 6,483 | 649 |
| 10100 | 장비 상자 | 0 | 0 |

- 아바타를 빼면 **약 650개, 71회 호출**로 거래소 전체를 한 바퀴 돌 수 있다.
- 각인서와 강화 재료(메인 페르소나의 관심사)만 수집하면 **184개, 19회**다.
- 강화 재료 안의 재련 재료(50010)는 33개, 4회다.

## 갱신 주기

재련 재료(50010) 가격순 첫 페이지를 18:13~18:22에 1분 간격으로 10회 호출했다. 상위 6개 아이템의 `CurrentMinPrice/RecentPrice`:

| 시각 | 운명의 파괴석 결정 | 운명의 파편 주머니(중) | 운명의 파편 주머니(대) | 나머지 3개 |
|---|---|---|---|---|
| 18:13:46 | 829/829 | 358/368 | 270/270 | 변화 없음 |
| 18:14:46 | **825/830** | 358/368 | **270/277** | |
| 18:15~18:16 | 같음 | 같음 | 같음 | |
| 18:17:47 | **829**/830 | 358/368 | **278/278** | |
| 18:18~18:20 | 같음 | 같음 | 같음 | |
| 18:21:49 | **827/827** | **355**/368 | **275/275** | |
| 18:22:49 | 같음 | 같음 | 같음 | |

- 값은 매분 바뀌지 않고 **3~4분 간격으로, 여러 아이템이 한꺼번에** 바뀌었다.
- 원본 API 쪽에서 일정 주기로 스냅샷을 갱신(또는 캐시)하는 것으로 보인다. 정확한 주기는 더 긴 측정이 필요하다 (`TODO`: 1시간 측정).
- 따라서 **갱신 주기보다 자주 호출해도 새 값을 얻지 못한다.** 우리 서비스가 낼 수 있는 신선도의 하한은 원본 갱신 주기(약 3~4분)다.

## 설계에 주는 영향

| 사실 | 영향 | 반영할 곳 |
|---|---|---|
| 검색 한 번에 10개 아이템의 시세가 온다 | 수집 단위는 아이템 하나가 아니라 **검색 페이지 하나**다 | [collector.md](../design/modules/collector.md), [00-architecture.md](../design/00-architecture.md) 미결 항목 |
| 페이지 구성은 정렬 기준에 따라 바뀐다 | 가격순으로 정렬하면 가격이 변할 때 아이템이 다른 페이지로 옮겨 간다. 페이지 단위로 수집하려면 **이름순이나 등급순처럼 고정된 정렬**을 써야 하고, 그래도 아이템이 추가되면 밀릴 수 있다 | collector.md |
| 분당 100회, 한 바퀴 71회 | 아바타를 빼면 거래소 전체를 **1분에 한 바퀴** 돌 수 있다. Hot/Normal/Cold 등급제(M4)의 의미는 "한도가 부족해서"가 아니라 아바타를 포함하거나 수집 대상을 늘릴 때, 그리고 상세 차트 호출과 한도를 나눠 쓸 때 생긴다 | [05-milestones.md](05-milestones.md) 성공 지표, D 결정 추가 |
| 원본 값은 3~4분 간격으로 바뀐다 | "Hot 아이템 갱신 지연 1분 이내" 목표는 원본 기준으로 달성할 수 없다. 지연은 **원본이 바뀐 뒤 우리가 그 값을 가져오기까지의 시간**으로 다시 정의해야 하고, 수집 스케줄러는 원본 갱신 시점을 추정해 그 직후에 호출을 몰아주는 방향이 의미 있다 | [05-milestones.md](05-milestones.md) 성공 지표, collector.md |
| 가격은 묶음 기준이다 | 화면과 알림에서 개당 가격을 보여줄지 정해야 한다 | [01-glossary.md](01-glossary.md) 묶음 단위 항목 |
| 같은 아이템이 거래 가능 횟수별로 나뉜다 | 시세의 식별자는 `Id`만으로 부족할 수 있다. 검색 결과에는 하나만 나오므로 어느 쪽인지 확인 필요 (`TODO`) | [02-data-model.md](../design/02-data-model.md) |
| 일별 통계는 14일치만 온다 | 14일이 넘는 차트는 직접 쌓은 스냅샷으로 그려야 한다 | 02-data-model.md |

## 아직 확인하지 못한 것

- 보석은 거래소가 아니라 경매장(`/auctions`) 데이터다. 경매장 API는 호출 비용과 응답 구조가 다르므로 MVP 수집 대상에서 뺄지 결정이 필요하다.
- 호출 한도를 넘었을 때의 응답 코드와 본문 (429로 예상, 일부러 넘기지 않았다).
- 검색 결과의 `TradeRemainCount`가 상세의 어느 항목과 대응하는지.
