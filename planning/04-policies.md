# 04. 서비스 정책

## 4.1 데이터 신선도

수집 스케줄러의 목표치이자, 사용자 화면에 보이는 약속이다.

### 신선도의 정의

로스트아크 API의 원본 시세는 매 순간 바뀌지 않고 몇 분 간격으로 한꺼번에 바뀐다 ([07-api-findings.md](07-api-findings.md#갱신-주기)). 원본보다 신선할 수는 없으므로, 신선도는 **원본이 바뀐 뒤 우리 서비스에 반영되기까지의 시간(반영 지연)**으로 잰다 ([D27](../design/decisions.md#d27-신선도는-원본이-바뀐-뒤-반영하기까지의-시간으로-재고-스케줄러는-원본-갱신-시점을-추적한다)).

### 아이템 등급별 반영 목표

| 등급 | 대상 | 반영 목표 (가안) |
|---|---|---|
| Hot | 활성 알림이 걸렸거나 관심 등록이 많은 아이템, 급변동 중인 아이템 | 원본 변경 후 30초 이내 |
| Normal | 나머지 주요 아이템 (재련 재료, 각인서) | 원본 변경 후 2분 이내 |
| Cold | 거래가 거의 없는 아이템 | 원본 변경 후 10분 이내 |

- 등급은 고정이 아니라 **사용자 행동(알림, 관심 등록)과 시세 변동에 따라 자동으로 바뀐다.**
- 실제 운영 범위(아바타 제외 약 650개, D26)는 1분에 한 바퀴를 돌 수 있어 모든 등급이 거의 같은 시점에 반영된다. 등급의 차이는 한도가 부족할 때(장애 후 밀린 호출, 시뮬레이터의 아이템 1만 개 실험) 드러난다.
- 수치는 가안이다. 원본 갱신 주기 측정과 M1 기준선을 본 뒤 확정한다.

### 화면 표시 규칙

| 상태 | 표시 |
|---|---|
| 갱신 목표 이내 | "마지막 갱신: N초 전" + ● 실시간 |
| 목표 초과 | 🟡 "갱신 지연" 배지 |
| 30분 이상 갱신 없음 또는 API 장애 | 🔴 상단 배너 "시세 수집이 지연되고 있어요". 마지막 값은 그대로 표시 |
| 게임 정기 점검 | 상단 배너 "게임 점검 중. 점검 전 시세입니다" |

## 4.2 목표가 알림

| 항목 | 정책 |
|---|---|
| 판정 기준가 | 거래소 현재 최저가 |
| 발송 방식 | **1회성**. 발송되면 '발송 완료'가 되고, 사용자가 다시 켜야 재사용한다 |
| 등록 한도 | 사용자당 활성 알림 최대 20개 |
| 발송 지연 목표 | 시세가 갱신된 뒤 1분 이내 |
| 중복 방지 | 같은 알림은 한 번 켜진 동안 **1번만 생성**된다. 단, 발송 직후 서버가 죽는 드문 경우 같은 DM이 다시 갈 수 있다 (누락보다 중복을 택함) |
| 발송 실패 | 사용자 쪽 원인(서버 이탈, DM 수신 거부)이면 즉시 실패 처리하고 웹 배너로 안내한다. 디스코드 일시 장애면 1시간 동안 재시도한다. 실패하면 웹 알림 내역에 "DM 전송 실패"로 남긴다 |
| 웹 인앱 알림 | 접속 중일 때만 토스트로 표시한다. 미접속이면 알림 내역에만 기록한다 |

**1회성으로 정한 이유**: 반복 발송은 시세가 기준가 근처에서 오르내릴 때 알림이 폭주한다. 이를 막으려면 쿨다운이나 히스테리시스 규칙이 추가로 필요하므로, MVP에서는 단순하게 간다. 반복 알림은 로드맵 후보다.

## 4.3 급변동 알림 (F11, P1)

| 항목 | 정책 |
|---|---|
| 급변동 기준 | 최근 1시간 안에 가격이 ±10% 이상 변동 |
| 오탐 방지 | 거래량이 적은 아이템은 제외한다 (기준은 수집 데이터를 보고 확정) |
| 쿨다운 | 같은 아이템은 1시간에 1번만 알린다 |
| 구독 | 기본값 꺼짐. 설정에서 직접 켠다 |

## 4.4 계정과 디스코드 DM 수신

### 전제가 되는 디스코드 제약

- 봇은 **같은 서버에 있는 사용자에게만** DM을 보낼 수 있다. 사용자가 봇을 개인 계정에 설치하는 방식(User Install)이어도 마찬가지다.
- 같은 서버에 있어도, 사용자가 개인정보 설정에서 "서버 멤버의 DM 허용"을 끄면 DM이 실패한다.

### 정책

| 항목 | 정책 |
|---|---|
| 로그인 | 디스코드 OAuth만 지원. 요청 권한은 `identify`, `guilds.join` |
| 사전 고지 | 로그인 버튼 아래에 "로그인하면 알림 수신을 위해 LoaPulse 디스코드 서버에 참여합니다"를 표시한다 |
| 서버 자동 참여 | 로그인 완료 시 봇이 사용자를 LoaPulse 서버에 추가한다. 이미 멤버면 그대로 넘어간다 |
| 수신 확인 | 최초 로그인 시 테스트 DM으로 수신 여부를 확인한다 |
| 탈퇴 | 즉시 계정, 알림, 관심 아이템을 삭제한다 |
| 저장하는 개인정보 | 디스코드 ID, 닉네임, 아바타만 저장한다 |
| `guilds.join` 토큰 | 서버 참여 시점에만 쓰고 **저장하지 않는다** |

서버 자동 참여에는 봇이 LoaPulse 서버의 멤버이고 초대 생성(`CREATE_INSTANT_INVITE`) 권한을 가져야 한다. ([Discord 공식 문서 - Add Guild Member](https://docs.discord.com/developers/resources/guild))

### LoaPulse 디스코드 서버 운영 원칙

들어온 서버가 시끄러우면 사용자가 바로 나가므로 **알림 수신 전용 서버**로 조용하게 운영한다.

- 채널은 공지 채널 하나만 두고, 채팅은 막는다.
- 서버 알림 기본값을 "알림 없음"으로 설정한다.
- 서버 소개에 "DM 알림을 받기 위한 서버입니다. 나가면 DM 알림이 중단됩니다"를 명시한다.

### DM 실패 대비책

| 상황 | 대응 |
|---|---|
| 사용자가 서버를 나감 | 다음 DM 실패 시 감지 → 웹 상단 배너와 [서버 다시 참여] 버튼(초대 링크) 제공 |
| DM 수신 설정이 꺼져 있음 | 웹 배너로 "디스코드 설정에서 서버 멤버 DM을 허용해 주세요" 안내 |
| 어떤 이유든 DM 실패 | 알림은 웹 알림 내역에 항상 남는다 (4.2) |

## 4.5 외부 API와 약관 준수

| 항목 | 정책 |
|---|---|
| 데이터 출처 | 로스트아크 공식 Open API만 사용한다. 웹 스크래핑은 하지 않는다 |
| API 키 | **키 1개 원칙**. 여러 키를 번갈아 쓰지 않는다 (약관 리스크가 있고, 제약 안에서 해결하는 것 자체가 프로젝트의 핵심 과제다) |
| 수익화 | 광고와 유료 기능 없음 |
| 출처 표기 | 모든 페이지 하단에 "데이터 출처: 로스트아크 Open API"를 표기한다 |

## 4.6 실시간 연결

| 상황 | 동작 |
|---|---|
| 실시간 연결 끊김 | "실시간 연결 끊김, 재연결 중" 표시 후 자동 재연결 |
| 재연결 성공 | 끊긴 동안 놓친 시세는 최신 값으로 한 번에 갱신 |
| 장시간 미사용 탭 | 탭이 숨겨진 상태로 10분이 지나면 연결을 끊고, 다시 볼 때 재연결 |
