# 06. 참고 서비스 분석

> 이미 운영 중인 로스트아크 시세·알림 서비스를 관찰해 도메인 이해를 보완하고, 그 결과를 설계 근거로 남긴다.
> M0 사전 조사에서 채운다. 아직 확인하지 않은 칸은 `TODO`로 둔다.

## 목적과 원칙

- **목적**: 로아를 플레이하지 않아서 생기는 도메인 이해 부족을 보완한다 ([05-milestones.md](05-milestones.md) 리스크 참고). 실제 유저가 보는 화면에서 어떤 아이템과 지표가 중요한지 확인한다.
- **관찰만 한다.** 다른 서비스의 코드, 에셋, 내부 API는 가져다 쓰지 않는다.
- **데이터는 공식 Open API로만 가져온다.** 참고 서비스에서 데이터를 수집하지 않는다.
- **관찰은 일반 사용 수준으로만 한다.** 브라우저로 직접 열어 보는 정도로 제한하고, 자동으로 반복 호출하지 않는다.
- 브라우저 관찰(네트워크 요청, 갱신 방식)에는 개발자 도구 같은 분석 도구를 쓸 수 있다. 결과에는 관찰한 날짜를 함께 적는다.

## 공통 관찰 항목

사이트마다 아래 항목을 같은 기준으로 기록한다.

| ID | 항목 | 확인할 내용 |
|---|---|---|
| O1 | 아이템 분류 | 어떤 카테고리가 있고, 첫 화면 상단에 어떤 아이템이 나오는가 |
| O2 | 표시 지표 | 현재가, 전일 평균, 변동률, 최근 거래가 중 무엇을 어느 화면에 보여주는가 |
| O3 | 갱신 방식 | polling, SSE, WebSocket 중 무엇을 쓰고 주기는 얼마인가. 갱신 상태를 화면에 어떻게 표시하는가 |
| O4 | 차트 | 기간 선택지와 데이터 간격 |
| O5 | 알림 | 조건을 어떻게 설정하고 어떤 채널로 받는가 |
| O6 | 호출 제한 대응 | API 호출 한도를 어떻게 나눠 쓰는가 (공개된 범위에서만) |
