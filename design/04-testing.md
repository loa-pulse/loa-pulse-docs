# 04. 테스트 전략

## 원칙

- **H2는 쓰지 않는다.** 조건부 갱신, `SKIP LOCKED`, 파티션은 PostgreSQL에서만 정확히 동작한다. 통합 테스트는 Testcontainers로 실제 PostgreSQL과 Redis를 띄운다.
- **시간은 모두 `Clock`으로 주입한다.** "1분 주기", "1시간 쿨다운", "생성 후 1시간이면 실패" 같은 규칙을 실제 시간을 기다리지 않고 테스트하기 위해서다.
- **추측으로 만든 외부 응답으로 테스트하지 않는다.** 외부 API 응답 예시는 M0에서 실제로 받은 응답을 저장해서 쓴다.
- 문제를 먼저 재현하는 테스트(재현 먼저)는 쓰지 않는다. 동시성 테스트는 올바른 구현을 검증하는 용도로만 쓴다.

## 1. 도메인 단위 테스트

DB나 스프링 없이 순수 자바로 테스트한다. 가장 많이, 가장 빠르게 돈다.

| 대상 | 검증할 것 (예) |
|---|---|
| `TierPolicy` | 활성 알림이 있으면 HOT, 거래량이 기준 이하면 COLD |
| `CollectionPlanner` | 지연 비율 순으로 고르고, 예산을 넘지 않는다 |
| `CallBudget` | 응답 헤더로 남은 횟수를 보정하고, 재시도 여유분을 지킨다 |
| `PriceAlert` | `ACTIVE`일 때만 `TRIGGERED`가 된다. 이상/이하 조건 판정 |
| `SurgeDetector` | ±10%, 거래량 기준, 1시간 쿨다운 |
| DM 실패 분류 | 디스코드 오류 코드 → 사용자 쪽 원인 / 일시 장애 (D21) |

## 2. 통합 테스트 (Testcontainers)

| 대상 | 검증할 것 |
|---|---|
| 알림 조건부 갱신 | 같은 알림에 시세 이벤트 두 개가 동시에 와도 `TRIGGERED` 전이는 1번만 성공한다 (D3) |
| 발송 워커 `SKIP LOCKED` | 워커 두 개가 동시에 돌아도 같은 알림을 함께 가져가지 않는다 (D14) |
| 선점 만료 | 워커가 발송 도중 죽었다고 가정하면, 만료 후 다른 워커가 다시 가져간다 (D14) |
| 파티션 관리 | 앞으로 3일치 파티션을 만들고, 3일 지난 파티션을 삭제한다 (D17) |
| 롤업 | 원본에서 일별 시가·고가·저가·종가가 정확히 계산된다 (D16) |
| 회원 탈퇴 | 알림 데이터까지 한 트랜잭션으로 삭제되고, 중간에 실패하면 전부 롤백된다 (D19) |

## 3. 외부 API 테스트 (WireMock)

로스트아크와 디스코드 클라이언트는 WireMock으로 가짜 서버를 띄워 테스트한다.

- 정상 응답, 5xx, 타임아웃, 429(응답 헤더 포함), 디스코드의 사용자 쪽 오류 코드
- 서킷 브레이커가 열리고 닫히는 흐름 (D20)

## 4. 아키텍처 테스트 (ArchUnit)

[00-architecture.md](00-architecture.md)의 모듈 경계 규칙을 테스트로 검사한다 (D6).
테이블 접근은 ArchUnit이 잡지 못하므로 코드 리뷰로 지킨다 (D18).

## 5. 프론트엔드

AI로 작성하고 코드를 거의 보지 않으므로, 테스트 코드보다 CI에서 자동으로 걸러내는 장치에 집중한다.

- OpenAPI에서 타입을 다시 생성했을 때 차이가 생기면 CI 실패 (백엔드 API가 바뀌었는데 프론트엔드가 따라가지 않은 경우)
- 타입 검사, 빌드 성공

## 6. 성능 측정: 로스트아크 API 시뮬레이터

[D23](decisions.md#d23-수집-스케줄러-비교-실험은-로스트아크-api-시뮬레이터에서-한다)

포트폴리오의 메인 스토리는 "M1의 단순한 수집기 대비 M4 등급제 스케줄러가 신선도를 얼마나 개선했나"다. 이 비교를 같은 조건에서 하기 위해 **로스트아크 API를 흉내 내는 시뮬레이터**를 만든다.

| 시뮬레이터가 흉내 내는 것 | 조절할 수 있는 값 |
|---|---|
| 분당 호출 제한과 응답 헤더 | 제한 횟수 |
| 아이템 목록과 검색 응답 | 아이템 수 (예: 1,000개, 1만 개) |
| 가격 변동 | 변동 빈도, 급변동 발생 |
| 장애 | 5xx 비율, 응답 지연, 점검 |

| 측정 | 환경 | 보여주는 곳 |
|---|---|---|
| 스케줄러 비교 실험 (M1 기준선 vs M4) | 시뮬레이터 | README, 기술 블로그 |
| 부하 테스트 (k6: SSE 동시 접속, 알림 처리량) | 시뮬레이터 | README, 기술 블로그 |
| 실제 운영 수치 | 실제 로스트아크 API | Grafana 공개 대시보드 (D22) |

- 시뮬레이터는 외부 API 테스트에 쓰는 WireMock을 확장하거나 작은 스프링 앱 하나로 만든다. 구현 방식은 M1 작업 목록에서 정한다.
- M1이 끝날 때 기준선을 측정해야 하므로 **M1 범위에 넣는다.**
- 응답 형식은 M0에서 받은 실제 응답을 따른다.
